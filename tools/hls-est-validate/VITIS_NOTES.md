## N1. Dead producer arrays are deleted before BRAM allocation (confirmed on the attention kernel)
- **Rule:** an array whose stored values cannot reach a top-level output is removed entirely (no memory, no BRAM), together with the computation feeding it. In forgebench `attention_op_p1`, `scale = (ap_fixed<16,5>)1.0 / hls::sqrt((ap_fixed<16,5>)16)` folds to a value that makes `scores[i][j] *= scale` a `store i16 0`; Q and K then feed nothing and are deleted, and so are the globals `BRAM_weights_q`/`BRAM_weights_k` that only fed Q and K.
- **Evidence:** `manual/attention_op_p1` run: `db/a.g.ld.5.gdce.ll` still has `%Q`, `%K` allocas (1 each) and the four `@BRAM_weights_*` globals; `db/a.o.1.ll` has no `%Q`/`%K` at all and `db/a.o.3.ll` keeps only `@BRAM_weights_v`, `@BRAM_attn_input`, `@BRAM_1` (`store i16 0, i16* %scores_addr` at a.o.3.ll:413). `top_csynth.rpt` memory table lists only `BRAM_attn_input_U` (2), `BRAM_1_U` (2), `BRAM_weights_v_U` (64). Total 73 BRAM (td=off), of which 2 are the `mem1_m_axi` adapter.
- **Headers:** with the real `ap_fixed.h`, `(ap_fixed<16,5>)16` has raw bits 0x8000 = -16.0 (AP_WRAP), `hls::sqrt(-16.0)` returns raw 0, and `1.0/0` traps in software (SIGFPE); the synthesized constant is whatever the fixed-point divider returns for /0 (to be read from `a.o.3.ll`).
- **hls-est:** not modelled (no dead-array elimination; globals always counted). Pass to add: a dead-memory elimination seeded from top-level outputs, plus fixed-point constant folding in the frontend shim/IR (CLAUDE.md step 2).

## N1a. Dead-array elimination, constant folding, globals, callees, interfaces (confirmed; 35 kernels, `~/hls-est-work/exp-notes/dead_globals.md`)
- **Dead arrays:** an array (local or file-scope global, static or not) whose loads never reach a top-level output argument is removed in the first HLS optimisation stage (`a.o.1`), together with everything that only fed it: write-only arrays, arrays read only into another dead array, arrays read into a value that is later overwritten, and arrays whose only consumer is multiplied by a folded constant 0 (int and ap_fixed). No log message reports it; the array simply has no memory row.
- **No cross-loop DSE/forwarding:** `store x` loop, then `store 0` loop, then read loop keeps all three loops and the array (1 BRAM). Do not model "fully overwritten before read".
- **ap_fixed folding (synthesis):** `(ap_fixed<16,5>)16` -> raw 0x8000 (-16), `hls::sqrt(-16)` -> 0, `1.0/0` -> 0 in every arithmetic use (`in + 1/0` -> `in`, `in * scale` -> `store i16 0`); control `1/sqrt(4)` = 0.5 (`lshr 1`). Kernels `dg_d_fold_steps`, `dg_d_apfixed16` (Q, K gone; 2 BRAM) vs `dg_d_apfixed4` (Q, K kept, replicated; 8 BRAM).
- **Constant-initialised arrays:** one unconditional full-range loop storing a constant turns the array into a ROM with the constant's width (`buf[i]=5` -> `512x3 ROM_AUTO_1R`, 1 BRAM); an all-zero ROM disappears (0 BRAM). Two loops / conditional / folded constants do not trigger this, but the stored-value range still narrows the element width (`512x1`, 0 BRAM).
- **Globals = locals:** same core, same BRAM, same elimination (`dg_e_globals_static` = `dg_e_globals_extern` = `dg_e_locals` = 4 BRAM). hls-est's "globals are always RAM_1P" special case is wrong.
- **Where an array is charged:** the module of the lowest common ancestor of its accessors, once. A non-inlined callee (`#pragma HLS inline off`, or large) called twice shares ONE instance (its array counted once); an inlined callee gets one copy per call site (`buf`, `buf_1`). Small static callees are auto-inlined.
- **Interfaces:** top-level array arguments never appear in memory tables (ap_memory costs 0). An `m_axi` bundle adds an adapter instance `<bundle>_m_axi_U` with BRAM from its read FIFO: depth D = max_read_burst_length x num_read_outstanding (default 16x16 = 256), bus width W = max(32, element bits); D <= 32 -> 0, else ceil(W/18) for D <= 1024 (2 for 32-bit, 4 for 64-bit), 8 at D = 4096; write side 0 at the default burst 16, 2 at burst 64 (formula unconfirmed beyond the 12 points). This is the `mem1_m_axi_U = 2` in forgebench tops.
- **hls-est:** needs (i) a dead-memory elimination seeded from top outputs run after constant folding, with integer/fixed `x*0 -> 0` and `x/0 -> 0`; (ii) globals handled like allocas; (iii) m_axi adapter cost from the `hls.interface` attributes; (iv) one copy per non-inlined callee instance.

## N2. throughput-driven array partitioning changes everything (confirmed)
- **Rule:** with the 2025.1 default `syn.array_partition.throughput_driven=auto`, an array read R times per iteration of an auto-pipelined loop is partitioned (`[HLS 214-270] Inferring pragma 'array_partition type=complete dim=2' for array 'buff_A' due to pipeline pragma`), e.g. plain polybench/atax: buff_A -> 64 banks of 64x32 = 64 BRAM, total 68. With `off` (Peter's configuration, used for all ground truth here) buff_A stays one 8-BRAM RAM and the loop runs at II 32-36.
- **Evidence:** `vitis-cache/polybench/atax/36433f38cda6d555` (auto run, 68) vs `manual/atax_tdoff` and the td=off cache entry (13).
- **hls-est:** `--infer-vitis-split-array` models the `auto` behaviour; under td=off it should not split arrays for port pressure. To be settled by the ablation.

## N3. Automatic pipelining, unrolling and flattening (confirmed, 61 kernels, `~/hls-est-work/exp-notes/pipeline_unroll.md`)
- **Threshold:** `syn.compile.pipeline_loops` (default 64; option documented in `A:\Vitis\2025.1\Vitis\data\hls\hls_ide_config_data.json`): a loop with trip count > 64 is pipelined itself; a loop with trip count <= 64 (64 included) is unrolled into a pipelined parent. Trip count, not bound (`j<128; j+=2` = 64 trips -> unrolled). Nothing else gates the unroll (body size, data-dependent if/break, float chains).
- **Algorithm** (reproduces all 61 runs): (1) collapse perfect nests into one loop with product trip count (perfectness judged after LICM/scalar promotion: a j-invariant load `lb[i]` makes the nest imperfect, hoisted pure arithmetic does not; `lo[i] +=` is register-promoted and therefore imperfect); (2) top-down, a (collapsed) loop P is pipelined iff every loop nested anywhere inside it (including loops in non-inlined callees) has a constant trip count and the product of trip counts along every nesting path inside P is <= 64; everything inside P is then completely unrolled; a loop with no inner loops is always pipelined (never unrolled on its own); if P fails, recurse into its children; (3) a non-pipelined parent Q with exactly one pipelined child C and constant bounds is converted to a perfect nest (extra code sunk/predicated) and flattened with C into one pipelined loop of trip(Q)*trip(C) (recursively upward); not when Q has two sibling child loops, a variable-trip child, or the child is in a non-inlined callee.
- **Consequences:** imperfect nest with inner <= 64 -> inner unrolled, parent pipelined (atax lp1/lp2); inner > 64 -> inner pipelined, parent flattened; perfect nests of any size are never unrolled, only flattened; a sibling loop > 64 or with variable trip makes the parent non-pipelined and leaves the small siblings pipelined (not unrolled); `pipeline_loops=0` disables everything.
- **hls-est:** `--auto-pipeline-unroll` unrolls innermost loops with trip > 32 (inverted) and only one level; `--infer-vitis-split-array` assumes "innermost = pipelined". Both must follow the algorithm above (track T3).

## N4. Memory replication, RAM_1WNR (confirmed, 56 kernels, `~/hls-est-work/exp-notes/replication.md`)
- Per pipelined loop L and local array X: R = loads/iteration, W = stores/iteration (after unrolling, CSE, LICM), II = final II. If some loop body has W > 1 -> **no replication**: X stays a plain 2-port RAM and the read loop gets II = ceil(R/2) (this is why hlsfactory atax's buff_A, written 64x per iteration of the unrolled copy-in, stays one 8-BRAM RAM with lp1 at II 32; splitting the copy-in into a perfect nest gives 15 copies, II 4, 120 BRAM). Else if ceil((R+W)/II) <= 2 -> plain RAM. Else `RAM_1WNR` with copies = ceil((R+W)/II) - 1, capped at 16 (17 reads/cycle: 16 port-B reads + the shared write port A reading when idle); if nothing else limits the loop, II = ceil((R+W)/17). The II of other constraints (another array's write ports, interface ports, a pragma II, a dependence) is taken first and the copies shrink (8 reads at II 4 -> 1 copy = the attention V case). No BRAM budget: 15 copies x 64 BRAM are reported on a 280-BRAM part.
- **Cost per copy** = true-dual-port aspect (max 18 data bits per port): 4096x32 -> 8, 4096x16 -> 4, 4096x8 -> 2, 4096x64 -> 16, 64x32 -> 2 (but the same 64x32 read in one loop and written in another costs 1). Copies of < 1024-bit arrays are LUTRAM (0 BRAM).
- **Loop-invariant reads are hoisted** (not counted) when the array is not stored in that loop and the nest is not flattened; in a flattened perfect nest the outer index varies, so `buff_A[i][k]` with k unrolled IS replicated (gemm-style corpus loops).
- **Partition inference still happens with td=off:** `[HLS 214-270] array_partition complete` for an array whose write loop is an unrolled inner loop of a pipelined loop (constant indices after unrolling) unless some access indexes that dimension with a variable; partitioned arrays are banks, not copies.
- **hls-est:** no replication model (> 2 accesses/cycle = "infeasible"); implemented in track T2 as: port model 17 slots/cycle for replicable banks, 2 otherwise; copies = ceil((R+W)/II)-1; per-copy x16 cost.

## N6. BRAM_18K count per bank: aspect-ratio modes with parity bits (confirmed, 147 kernels, `~/hls-est-work/exp-notes/aspect.md`)
- **Rule:** for a bank of D words x W bits, `BRAM = min over modes m of ceil(W/m) * max(1, P/depth(m))` with `P = 2^ceil(log2 D)` (the address space, not the word count: 2500x18 one-port = 4, not 3; `~/hls-est-work/exp-notes/aspect_chk.md`) and `(m, depth) in {(1,16384), (2,8192), (4,4096), (9,2048), (18,1024), (36,512)}`; the x36 mode is allowed only when at most one port is live per cycle (or the storage is `ram_s2p`); when two ports are live in the same cycle (`ram_2p`/`ram_t2p`, e.g. a read and a write or two reads per iteration of a pipelined loop) the x18 ceiling applies. All columns use the same mode; parity bits count (1024x18 = 1, 2048x9 = 1, 512x36 = 1, 1024x17 = 1, 1024x24 = 2, 1024x40 = 3 one-port / 3 two-port, 2048x72 = 8).
- The declared `bind_storage` type does not change the count by itself; the number of ports the schedule uses does. The `Storage Report` / `design.bindinfo.xml BRAM=` numbers use x18-only packing and are NOT the utilization numbers; only the `* Memory:` table / csynth.xml total count.
- float = 32 bits, double = 64; `ap_int<18>` = `ap_uint<18>`; 1024x1 is a 1-BRAM RAM (consistent with the inclusive 1024-bit threshold).
- **hls-est:** `estimateBlocks` uses pow2 widths and 16384 data bits (no x9/x18/x36): over-counts 17-18, 33-36, 40-48 and 72-bit elements and 9-bit elements; must implement the min-over-modes formula with the one-port/two-port distinction (track T2).

## N7. Partition pragmas, reshape, bind_storage and the automatic partitions that remain with td=off (confirmed, 136 kernels, `~/hls-est-work/exp-notes/partition.md`)
- **array_partition** `{cyclic|block} factor=F dim=d` -> exactly F banks, each `ceil(N_d/F) x (product of the other dims)` words; cyclic/block and dim=1/2 cost the same BRAM. `complete dim=1|2` on a 2-D array -> N_d memory banks (64x32 banks = 1 BRAM each, not registers); only `complete dim=0` or `complete` on a 1-D array removes the memory (registers, 32 FF per element). Bank naming `A_U`, `A_1_U`, ... all sharing module `A_RAM_AUTO_1R1W`.
- **array_reshape** `factor=F` -> one memory of N/F words x F*W bits (64x64 int F=4 -> 1024x128 = 8 BRAM; `complete dim=2` -> 64x2048 bits = 114 BRAM, bound ram_2p).
- **bind_storage** types ram_1p/2p/s2p/t2p cost the same as the auto core for the same access pattern: the count follows the ports used per cycle (ram_1p/s2p with 2 reads per cycle keep 1 BRAM but the loop gets II=2).
- **Port mode:** `ram_1p` when no cycle touches the bank twice; `ram_2p` (18-bit columns) when a cycle holds two accesses (two reads, read+write, or two constant-index reads issued in the same state); `RAM_1WNR` with R-1 copies when a cycle needs R >= 3 reads. Any in-place update of a local array inside a pipelined loop (`acc[i] += ...`) therefore costs the 18-bit column (64x32 -> 2).
- **Automatic partitions with td=off:** (a) `[HLS 214-421]` arrays with <= 4 elements in total (any width/dims) become registers (0 BRAM, alloca gone); (b) `[HLS 214-449]` a dimension whose EVERY access (after unrolling, in every loop) is a constant index is completely partitioned on that dimension (A[64][8] with j unrolled in both loops -> 8 banks of 64x32); (c) an array whose every access is a constant index is scalarised (no memory); (d) a 1-D array written with a variable index and read only at constant indices is NOT partitioned (stays one ram_2p RAM). Order in the log: 214-421/214-449, then 214-270, then 214-248; all before `a.o.1`.
- **Depth rounding (same as N6):** 1100x32 -> 4, 2100x32 -> 8, 5000x32 -> 16, 12000x32 -> 32, 1408x32 (cyclic 3 on 64x64) -> 4.
- **hls-est:** banking must keep `ceil(N_d/F)` bank depth (it does) and the pow2 depth rounding + x36/x18 column rule from N6; `--infer-vitis-split-array` must implement (a)-(c) instead of port-pressure partitioning when td=off; `complete` on one dim must stay BRAM banks (hls-est's 1024-bit threshold already handles 64x32 = 2048 bits).

## N5. BRAM vs. distributed RAM for small arrays (confirmed, 23 kernels)
- **Rule:** a local array with `Words * Bits >= 1024` is implemented in BRAM_18K; with `Words * Bits < 1024` it becomes distributed RAM (memory row `BRAM_18K = 0`, `FF = Bits`, `LUT = ceil(Words*Bits/64)`). The threshold is inclusive and uses the exact element width (64x15 = 960 bits -> LUTRAM; 64x16 = 1024 -> 1 BRAM; 93x11 = 1023 -> LUTRAM; 16x64 = 1024 -> 2 BRAM). Depth alone is not the criterion (128x4 -> LUTRAM).
- **Kernels:** `~/hls-est-work/exp-src/lutram/lutram_d<depth>_w<bits>.cpp` (1-D buffer written in one auto-pipelined loop, read in another) and `lutram_chk_*` (ap_int<4>/<11>/<15> widths), reports `~/hls-est-work/experiments/lutram_*/<hash>/report/k_csynth.rpt` line 90, notes `~/hls-est-work/exp-notes/lutram_chk.md`.
- **Not yet checked:** whether the threshold changes for ROM (const arrays), 2-D arrays, partition banks, or arrays with two ports in use.
- **hls-est:** `MemoryInterface.cpp` `meetsBRAMPromotionThreshold` uses `sizeInBits > 1024` (strict); must be `>= 1024`. Element width already exact.
- **Side data point (aspect topic):** a 64x32 array with 1 read + 1 write in *different* loops costs 1 BRAM (not 2): the x16-per-port rule only applies when both ports are busy in the same cycle (true dual-port), as for atax's `buff_y_out` (read and written in the same pipelined loop, 2 BRAM).
