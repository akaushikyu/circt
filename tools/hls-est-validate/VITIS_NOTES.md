## N1. Dead producer arrays are deleted before BRAM allocation (confirmed on the attention kernel)
- **Rule:** an array whose stored values cannot reach a top-level output is removed entirely (no memory, no BRAM), together with the computation feeding it. In forgebench `attention_op_p1`, `scale = (ap_fixed<16,5>)1.0 / hls::sqrt((ap_fixed<16,5>)16)` folds to a value that makes `scores[i][j] *= scale` a `store i16 0`; Q and K then feed nothing and are deleted, and so are the globals `BRAM_weights_q`/`BRAM_weights_k` that only fed Q and K.
- **Evidence:** `manual/attention_op_p1` run: `db/a.g.ld.5.gdce.ll` still has `%Q`, `%K` allocas (1 each) and the four `@BRAM_weights_*` globals; `db/a.o.1.ll` has no `%Q`/`%K` at all and `db/a.o.3.ll` keeps only `@BRAM_weights_v`, `@BRAM_attn_input`, `@BRAM_1` (`store i16 0, i16* %scores_addr` at a.o.3.ll:413). `top_csynth.rpt` memory table lists only `BRAM_attn_input_U` (2), `BRAM_1_U` (2), `BRAM_weights_v_U` (64). Total 73 BRAM (td=off), of which 2 are the `mem1_m_axi` adapter.
- **Headers:** with the real `ap_fixed.h`, `(ap_fixed<16,5>)16` has raw bits 0x8000 = -16.0 (AP_WRAP), `hls::sqrt(-16.0)` returns raw 0, and `1.0/0` traps in software (SIGFPE); the synthesized constant is whatever the fixed-point divider returns for /0 (to be read from `a.o.3.ll`).
- **hls-est:** not modelled (no dead-array elimination; globals always counted). Pass to add: a dead-memory elimination seeded from top-level outputs, plus fixed-point constant folding in the frontend shim/IR (CLAUDE.md step 2).

## N1a. Dead-array elimination, constant folding, globals, callees, interfaces (confirmed; 35 kernels, `~/hls-est-work/exp-notes/dead_globals.md`)
- **Dead arrays:** an array (local or file-scope global, static or not) whose loads never reach a top-level output argument is removed in the first HLS optimisation stage (`a.o.1`), together with everything that only fed it: write-only arrays, arrays read only into another dead array, arrays read into a value that is later overwritten, and arrays whose only consumer is multiplied by a folded constant 0 (int and ap_fixed). No log message reports it; the array simply has no memory row.
- **Arrays filled by a non-inlined callee stay (seen in one design; unconfirmed as a rule):** forgebench tiled_attn_module keeps BRAM_A2/A3/B2/B3 as `RAM_AUTO_0R0W` memories (64 + 64 + 16 + 16 BRAM, counted in the total) although no load of them is left: the `load_*` functions that fill them from m_axi are not inlined in that design (8 `call @load_*` in `vitis-cache/forgebench/tiled_attn_module/cb47c24f230d6b37/db/a.o.1.ll:101-102`), so the arrays escape into a call. In attention_op_p1 and tiled_attn_p1 the same functions are inlined (no call at a.o.1) and the dead weight arrays are gone. cgeist inlines every callee (O10), so `--dead-memory-elimination` removes them (tiled_attn_module 110 vs Vitis 270 under the exactclass shim).
- **No cross-loop DSE/forwarding:** `store x` loop, then `store 0` loop, then read loop keeps all three loops and the array (1 BRAM). Do not model "fully overwritten before read".
- **ap_fixed folding (synthesis):** `(ap_fixed<16,5>)16` -> raw 0x8000 (-16), `hls::sqrt(-16)` -> 0, `1.0/0` -> 0 in every arithmetic use (`in + 1/0` -> `in`, `in * scale` -> `store i16 0`); control `1/sqrt(4)` = 0.5 (`lshr 1`). Kernels `dg_d_fold_steps`, `dg_d_apfixed16` (Q, K gone; 2 BRAM) vs `dg_d_apfixed4` (Q, K kept, replicated; 8 BRAM).
- **Division by a constant 0 (confirmed, T4 review; kernels `~/hls-est-work/exp-src/t4fix/dg_d_fold_divrem0{,b}.cpp`, each output `o[i] = a[j] + b[j] OP 0` over 1024-word local arrays, reports and IR in `~/hls-est-work/experiments/dg_d_fold_divrem0{,b}/<hash>/`):**
  - ap_fixed<16,5> `x / 0` -> **0** for a variable and a constant numerator (`dg_d_fold_divrem0b`: `o_fvar = a_fvar`, `o_fconst = a_fconst`, b_fvar removed; a.o.1.ll:80/85 `store i16 %a_fvar.load` / `%a_fconst.load`), as `dg_d_fold_steps`.
  - unsigned int `x % 0u` (variable x) -> **0** (`dg_d_fold_divrem0`: a.o.1.ll:80 `store i32 %a_urem.load` into o_urem; b_urem removed; a_urem 2 BRAM).
  - int `x / 0`, `x % 0` and unsigned `x / 0u` -> **undef**, variable or constant numerator: no store to o_sdiv / o_srem / o_udiv / o_cdiv / o_crem / o_cudiv is left at a.o.1, and both a_* and b_* arrays are removed (the frontend already writes `store i32 undef` for `7 / z`, a.g.ld.5.gdce.ll:396-402). Totals: divrem0 6 BRAM (a_urem, a_ctrl, b_ctrl), divrem0b 2 (a_fvar, a_fconst).
  - hls-est (T4) `--vitis-fold` folds divsi / divui / remsi / remui by a constant 0 to 0: exact for ap_fixed (an `arith.divsi` under the integer-backed exactclass shim, indistinguishable from a C int division in MLIR) and for unsigned `%`; for the C-int undef cases 0 is a refinement (every array it removes Vitis removes too, but Vitis also removes the other operands: divrem0 12 vs Vitis 6, O16). *Since T8 this is `--vitis-fold=undef=false`; the default models the undefined value per use (N13), which tells the two apart without knowing the source type: the fixed-point operators sign-extend U (0), a C int expression uses it directly (U). divrem0 6 and divrem0b 2 = Vitis.*
- **Constant-initialised arrays:** one unconditional full-range loop storing a constant turns the array into a ROM with the constant's width (`buf[i]=5` -> `512x3 ROM_AUTO_1R`, 1 BRAM); an all-zero ROM disappears (0 BRAM). Two loops / conditional / folded constants do not trigger this, but the stored-value range still narrows the element width (`512x1`, 0 BRAM).
- **Globals = locals:** same core, same BRAM, same elimination (`dg_e_globals_static` = `dg_e_globals_extern` = `dg_e_locals` = 4 BRAM). hls-est's "globals are always RAM_1P" special case is wrong.
- **Where an array is charged:** the module of the lowest common ancestor of its accessors, once. A non-inlined callee (`#pragma HLS inline off`, or large) called twice shares ONE instance (its array counted once); an inlined callee gets one copy per call site (`buf`, `buf_1`). Small static callees are auto-inlined.
- **Interfaces:** top-level array arguments never appear in memory tables (ap_memory costs 0). An `m_axi` bundle adds an adapter instance `<bundle>_m_axi_U` (an "Instance" row, not a memory row) whose BRAM comes from its read FIFO and its write buffer; 26 kernels (`dg_g_maxi_*` in dead_globals.md R8, plus 14 `mx_*` added in T4: `~/hls-est-work/exp-src/maxi/mx_*.cpp`, reports `~/hls-est-work/experiments/mx_*/<hash>/report/<kernel>_csynth.rpt:78`):
  - **Read FIFO (confirmed):** depth D = max_read_burst_length x num_read_outstanding (defaults 16 x 16 = 256), bus width W = max(32, element bits) (`m_axi_mem1_RDATA` is 32 for ap_int<16>, 64 for long long). D <= 32 -> 0 (D = 2, 16, 32); D > 32 -> the x18 bands of N8: D = 40 (8x5), 48 (16x3), 64 (16x4 and 32x2), 256, 1024 -> ceil(W/18) = 2 (W 32) / 4 (W 64, `mx_r_w64_b64`); D = 2048 (128x16, `mx_r_d2048`) -> ceil(32/9) = 4; D = 4096 -> 8 for W = 32 (`dg_g_maxi_r_b256`) and for ap_int<16> widened to 32 (`mx_r_w16_b256`). Only the product matters (32x2 = 16x4 = 2). Depths above 4096 untested.
  - **Write buffer (confirmed for the tested points):** 0 at max_write_burst_length 16 whatever num_write_outstanding (16, and 32: `mx_w_o32` 0); ceil(W/18) for bursts 32, 64, 128, 256 (`mx_w_b32`, `dg_g_maxi_w_b64`, `mx_w_b128`, `mx_w_b256` = 2 for W 32; `mx_w_w64_b64` = 4 for W 64); num_write_outstanding 1 with burst 64 still 2 (`mx_w_b64o1`), so the write depth is not burst x outstanding. Bursts 17-31 untested (unconfirmed).
  - **Read + write on one bundle add up** (`mx_rw_wb64`: 2 + 2 = 4; `dg_g_maxi_rw` at defaults: 2 + 0 = 2).
  - **Default bundle:** m_axi ports without `bundle=` share one bundle `gmem` (`mx_nobundle2`: two read ports -> one `gmem_m_axi_U`, 2 BRAM).
  - This is the `mem1_m_axi_U = 2` (and `mem2_m_axi_U = 0`) of every forgebench top in results/vitis.json (45 designs; mult_op_module_dot has three read bundles = 6).
  - **Accesses inside a sub-function count for the bundle (confirmed, T4 review):** `mx_call_rw` / `mx_call_rw2` (`~/hls-est-work/exp-src/t4fix/`; `rd` / `wr` with `inline off`, kept as modules `rd_Pipeline_*` / `wr_Pipeline_*`): mem3, only read inside `rd`, has `mem3_m_axi_U` = 2; mem2, only written inside `wr`, has no adapter BRAM (0), exactly like the same accesses in the top (`dg_g_maxi_r` 2, `dg_g_maxi_w` 0). Total 3 (buf 1).
  - **hls-est (T4):** `--bram-analysis --bram-maxi-adapters` (off by default, MEMOS.md M5) adds one pseudo-memref per (public function, bundle) of `hls.interface` entries with mode = "m_axi": read FIFO cost when an argument of the bundle is loaded, write cost when one is stored; an argument passed to a function defined in the module is followed into the callee (T4 review fix; before, any call counted as read + write: a write-only port through a call got 2 instead of 0), a callee without a body is still assumed to read and write it; stdout line `m_axi.adapter bundle=... bram=N`, debug kind `m_axi_adapter`. Reproduces all 27 kernels per bundle and in total on cgeist output (`~/hls-est-work/t4/maxi/`), and mx_call_rw2 (3 = Vitis; cgeist inlines `rd` / `wr` there, O10, so the call path is pinned by lit `maxi_adapter_call.mlir`).
- **hls-est (T4, all opt-in, MEMOS.md M5):** (i) `--vitis-fold` folds integer divsi / divui / remsi / remui by a constant 0 -> 0 (see "Division by a constant 0" for where that equals Vitis; ceildiv / floordiv are not folded, no C expression produces them with a zero divisor) together with the canonicalization folds, so x*0 -> 0 follows; float x*0.0 is not folded (IEEE), so ap_fixed needs an integer-backed frontend (the `exactclass` shim (c733e425e) emits exactly `arith.divsi 4194304, 0` for the attention scale); (ii) `--dead-memory-elimination` (liveness seeded from returns, calls, stores to arguments / escaping memory; per-element overwritten-store elimination including promotable read-modify-write chains; records the removed arrays in `hls.dead_memrefs` for `--bram-debug`); (iii) `--promote-globals-to-allocas` (uninitialised / zero globals used by one function become allocas) and `--bram-attribute-globals` (get_global accesses attributed; an initialised global that is `constant` or that no get_global site writes or lets escape is priced as a ROM, N8 - cgeist never emits `constant` for `static const T t[] = {...}`; T4 review kernel `rom2r_int`, a 512x32 table read twice per cycle: Vitis `tbl_ROM_AUTO_1R` 1 BRAM, hls-est 1 (was RAM_T2P 2)); (iv) the m_axi adapters above. Still missing: the ROM conversion of constant-initialised arrays and the stored-value width narrowing (R3/R4), and one copy per non-inlined callee instance (O10). On forgebench `attention_op_p1` cgeist + `exactclass` shim + the T4 cleanups + both flags give 73 = Vitis (BRAM_attn_input 2, BRAM_weights_v 64, BRAM_1 2, V 2, scores 1, mem1 adapter 2; Q, K, BRAM_weights_q, BRAM_weights_k eliminated as in a.o.1); the default scalar shim (f32) and `--shim exact` (f16: 1/sqrt(16) = 0.25) cannot fold the scale, so Q and K stay there (203 -> 205 with the adapter).

## N2. throughput-driven array partitioning changes everything (confirmed)
- **Rule:** with the 2025.1 default `syn.array_partition.throughput_driven=auto`, an array read R times per iteration of an auto-pipelined loop is partitioned (`[HLS 214-270] Inferring pragma 'array_partition type=complete dim=2' for array 'buff_A' due to pipeline pragma`), e.g. plain polybench/atax: buff_A -> 64 banks of 64x32 = 64 BRAM, total 68. With `off` (Peter's configuration, used for all ground truth here) buff_A stays one 8-BRAM RAM and the loop runs at II 32-36.
- **Evidence:** `vitis-cache/polybench/atax/36433f38cda6d555` (auto run, 68) vs `manual/atax_tdoff` and the td=off cache entry (13).
- **hls-est:** `--infer-vitis-split-array` models the `auto` behaviour; under td=off it should not split arrays for port pressure. To be settled by the ablation.

## N3. Automatic pipelining, unrolling and flattening (confirmed, 61 kernels, `~/hls-est-work/exp-notes/pipeline_unroll.md`)
- **Threshold:** `syn.compile.pipeline_loops` (default 64; option documented in `A:\Vitis\2025.1\Vitis\data\hls\hls_ide_config_data.json`): a loop with trip count > 64 is pipelined itself; a loop with trip count <= 64 (64 included) is unrolled into a pipelined parent. Trip count, not bound (`j<128; j+=2` = 64 trips -> unrolled). Nothing else gates the unroll (body size, data-dependent if/break, float chains).
- **Algorithm** (reproduces all 61 runs): (1) collapse perfect nests into one loop with product trip count (perfectness judged after LICM/scalar promotion: a j-invariant load `lb[i]` of an **integer** element makes the nest imperfect - a floating-point one does not, see "Floating-point invariant loads" below; hoisted pure arithmetic does not; `lo[i] +=` is register-promoted and therefore imperfect, whatever the element type); (2) top-down, a (collapsed) loop P is pipelined iff every loop nested anywhere inside it (including loops in non-inlined callees) has a constant trip count and the product of trip counts along every nesting path inside P is <= 64; everything inside P is then completely unrolled; a loop with no inner loops is always pipelined (never unrolled on its own); if P fails, recurse into its children; (3) a non-pipelined parent Q with exactly one pipelined child C and constant bounds is converted to a perfect nest (extra code sunk/predicated) and flattened with C into one pipelined loop of trip(Q)*trip(C) (recursively upward); not when Q has two sibling child loops, a variable-trip child, or the child is in a non-inlined callee.
- **Floating-point invariant loads (confirmed, 18 kernels, T3 review; `~/hls-est-work/exp-src/pipeline_unroll_float/*.cpp`, logs `~/hls-est-work/experiments/<kernel>/<hash>/log/hls_compile.log`):** the LICM rule above holds for integer elements only. `lo[i][j] = la[i][j] * lb[i]` with **float** `lb` is converted into a perfect nest and flattened (`[HLS 200-2061] Successfully converted nested loops 'VITIS_LOOP_8_4' and 'VITIS_LOOP_9_5' into perfectly nested loops`, `[XFORM 203-541] Flattening a loop nest 'VITIS_LOOP_8_4'`, one trip-512/4096 II-1 pipeline): rv_st_hoist_f_m64_n64, rv_rmw_hoist_f_m8_n64 / _m64_n64 (Vitis 3 / 11 BRAM), pf_fmul_m8_n64, pf_fadd_m8_n64, pf_fmac_m8_n32, pf_srchoist_m8_n64 (the load written in the outer body in the source, `float t = lb[i];`), pm_floatarr_iop_m8_n64 (float arrays, integer arithmetic through a union). Every integer twin is unrolled (`[HLS 214-186] Unrolling loop 'VITIS_LOOP_9_5'`, i pipelined at II 32): rv_st_hoist_m64_n64, rv_rmw_hoist_m8_n64 / _m64_n64 (32 / 123), pi_add_m8_n64, pi_mul3_m8_n64, pl_mul_m8_n64 (`long`), pi_srchoist_m8_n64, pm_intarr_fop_m8_n64 (int arrays, float arithmetic); pf_twoload_m8_n64 (one float and one int invariant load) is unrolled too. So it is the type of the loaded element, not of the arithmetic. A float accumulator that is register-promoted still makes the nest imperfect (pf_memred_m8_n16: j unrolled, i pipelined). Polybench (all float) hits it: atax `lp3_lp4` and bicg `lp1_lp2` are flattened 4096-trip II-1 pipelines (`results/vitis.json`), so atax `buff_y_out` and bicg `buff_s_out` need 2 BRAM (1R + 1W per cycle in the flattened pipeline). Mechanism unknown: the decision precedes `db/a.o.1.ll`, which shows `%lb.load` outside the j-loop body in the int and the float run alike (so LLVM LICM's placement is not the criterion). With the scalar shim `ap_fixed` is a float in MLIR while Vitis sees an `iN`: the rule must not be applied to ap_fixed designs from that shim.
- **Consequences:** imperfect nest with inner <= 64 -> inner unrolled, parent pipelined (atax lp1/lp2); inner > 64 -> inner pipelined, parent flattened; perfect nests of any size are never unrolled, only flattened; a sibling loop > 64 or with variable trip makes the parent non-pipelined and leaves the small siblings pipelined (not unrolled); `pipeline_loops=0` disables everything.
- **User `unroll` pragmas (confirmed on 4 corpus designs, T3):** a loop that keeps a partial `#pragma HLS unroll` (factor below its trip count, `factor=1` included) is never completely unrolled for an enclosing automatic pipeline: no loop around it is auto-pipelined, the loop itself is (and so is every copy a parent's partial unroll makes of it). Evidence (`results/vitis.json` loop tables + `hls_compile.log` 214-376/214-186 lines in the vitis-cache dirs): forgebench/diff_dims_p1 `gemm_ijk_bias` i/6, j/16, k/4 -> `VITIS_LOOP_138_5` (k, 32 trips) `pipe yes` in all 96 copies, `VITIS_LOOP_136_4` (j) and `134_3` (i) `pipe no`, no 214-291 "implied" unroll; forgebench/diff_orders_p1 (`133_5` x128 pipelined, parents not); forgebench/mult_op_p1 (`78_5`, 2 trips, pipelined x40, parents `65_1`/`74_3`/`76_4` not); spector_hls/fir (`factor=1` loops 62/70/102/120/134 pipelined, the 67-trip parent `VITIS_LOOP_53_3` not although every inner loop has <= 64 trips after the user unroll of 122). Complete user unrolls (factor >= trip, or 0) just remove the loop. The pragma is applied before the decision (a 256-trip loop `unroll factor=4` is a 64-trip loop with 4 bodies, pipelined itself). A factor that does not divide the trip count leaves no epilogue loop: the unrolled body keeps an exit check per copy (documented, UG1399 `skip_exit_check`; not measured here), i.e. ceil(N/F) iterations of F bodies.
- **hls-est:** modelled since the T3 commit (CHANGELOG "Vitis automatic pipeline/unroll/flatten decision"): `--auto-pipeline-unroll` (option `pipeline-loops`, default 64) applies user unrolls, collapses perfect nests (perfectness judged with an LICM/promotion model: a load at an inner-invariant address from an array the inner loop never writes is hoisted, a memory touched only at inner-invariant pairwise-disjoint addresses with a store is promoted), decides top-down with per-path products, unrolls everything under the pipelined loop (callee loops through `func.call` included), hoists/promotes out of the unrolled loops and (option `promote-pipelined`) out of the pipelined loop, tags `hls.pipeline = [{II = 0, source = "auto"}]`, `hls.flattened_parents = N` and `hls.auto_unrolled = [{factor, loc}]` (debug record, shown by `--bram-debug` / the JSON `pipelines` array) on the pipelined loop (user `hls.pipeline` kept and honoured, `hls.pipeline_off` never auto-pipelined, partial `hls.unroll` -> `hls.unroll_partial` on the main loop; MLIR's cleanup loop for a non-dividing factor is unrolled into straight-line code, T3 review fixes); `--infer-vitis-split-array` and `--convert-affine-to-loopschedule` read `hls.flattened_parents` through `getFlattenedRoot()` so the flattened ancestors' IVs stay loop-variant. Decision agreement with Vitis on the 69 pipeline_unroll(+_chk) kernels: 64/69 (`tools/hls-est-validate/check_pipeline_unroll.py`); the 5 others are the 4 `pu_call_*` kernels (cgeist inlines the `inline off` callee, so hls-est decides on the inlined nest; equivalent per loop) and pu_prefix (below). The floating-point rule is option `float-loads-perfect` (off by default pending Peter's decision, MEMOS.md M8); without it the 8 float kernels that Vitis flattens - and atax lp3/lp4, bicg lp1/lp2 - are decision mismatches (OPEN_ISSUES O13).
- **Unconfirmed (T3):** (a) pu_prefix_m8_n16 (`la[i][j] += la[i][j-1]`, syntactically perfect) is unrolled by Vitis (j x15, i pipelined) where every rule above says "flatten"; the likely cause is LLVM's LoopLoadElimination (the distance-1 store->load pair becomes a register recurrence and a prologue load `la[i][0]` lands in the i body, making the nest imperfect) - not modelled, OPEN_ISSUES O8. (b) `#pragma HLS pipeline off` on an inner loop whose parent is auto-pipelined: whether the parent still unrolls it (hls-est does). (c) A perfect nest whose outermost loop has a variable bound is flattened (semi-perfect, Vitis docs) - hls-est flattens; an inner variable bound is never flattened (confirmed, pu_var_inner).

## N4. Memory replication, RAM_1WNR (confirmed, 56 kernels, `~/hls-est-work/exp-notes/replication.md`)
- Per pipelined loop L and local array X: R = loads/iteration, W = stores/iteration (after unrolling, CSE, LICM), II = final II. If some loop body has W > 1 -> **no replication**: X stays a plain 2-port RAM and the read loop gets II = ceil(R/2) (this is why hlsfactory atax's buff_A, written 64x per iteration of the unrolled copy-in, stays one 8-BRAM RAM with lp1 at II 32; splitting the copy-in into a perfect nest gives 15 copies, II 4, 120 BRAM). Else if ceil((R+W)/II) <= 2 -> plain RAM. Else `RAM_1WNR` with copies = ceil((R+W)/II) - 1, capped at 16 (17 reads/cycle: 16 port-B reads + the shared write port A reading when idle); if nothing else limits the loop, II = ceil((R+W)/17). The II of other constraints (another array's write ports, interface ports, a pragma II, a dependence) is taken first and the copies shrink (8 reads at II 4 -> 1 copy = the attention V case). No BRAM budget: 15 copies x 64 BRAM are reported on a 280-BRAM part.
- **Cost per copy** = true-dual-port aspect (max 18 data bits per port): 4096x32 -> 8, 4096x16 -> 4, 4096x8 -> 2, 4096x64 -> 16, 64x32 -> 2 (but the same 64x32 read in one loop and written in another costs 1). Copies of < 1024-bit arrays are LUTRAM (0 BRAM).
- **Loop-invariant reads are hoisted** (not counted) when the array is not stored in that loop and the nest is not flattened; in a flattened perfect nest the outer index varies, so `buff_A[i][k]` with k unrolled IS replicated (gemm-style corpus loops).
- **Which II the copies are sized for is NOT the final II alone (unconfirmed, T3; OPEN_ISSUES O11):** pipeline_unroll.md pu_impst_m8_n16 (16 reads of `la` feeding a 16-term reduction, 16 independent stores of `lo` force the final II to 8): `[HLS 200-2167] ... with 15 copies`, 30 BRAM, i.e. sized for II 1; pu_red3c_l4_m4_n4 and pipeline_unroll_chk_4lvl likewise (final II 2, 15 copies). But pu_st_hoist_m8_n16 (16 reads of `la`, each feeding one of 16 independent stores `lo[i][j] = la[i][j]*lb[i]+1`, final II 8 from those stores): **no copies**, 4 BRAM. And spector_hls/fir (8 reads of `ai_a0`/`ai_b0` per iteration of `VITIS_LOOP_120_9`, whose II 6 comes from the `firReal[l] +=` recurrence after register promotion): one `RAM_1WNR_AUTO_1R1W` copy each (2 BRAM), sized for II 6. A rule "max(recurrence II, own port-limited II ceil((R+W)/17))" explains all but pu_st_hoist; the final-II rule (hls-est, T2) explains all but pu_impst/red3c/4lvl. The difference between pu_impst and pu_st_hoist is what the reads feed (a dependent reduction chain vs. independent stores), so the real criterion is schedule-driven (reads needed early are given copies). hls-est keeps the final-II rule; with the register promotion of T3 the recurrence of fir bounds the schedule II, so fir is exact.
- **Replication applies per partition bank (confirmed, `fu_part_rep`):** `int A[4096]` with `array_partition cyclic factor=2` read 8x per iteration of an II=1 loop (4 reads per bank) -> each bank becomes `RAM_1WNR` with 3 copies: `A_U` 12 + `A_1_U` 12 = 24 BRAM (2048x32 narrow = 4 per copy). hls-est's bank x copies product matches (`~/hls-est-work/experiments/fu_part_rep/3870ada35ab1`).
- **Partition inference still happens with td=off:** `[HLS 214-270] array_partition complete` for an array whose write loop is an unrolled inner loop of a pipelined loop (constant indices after unrolling) unless some access indexes that dimension with a variable; partitioned arrays are banks, not copies.
- **hls-est:** modelled since the T2 commit (CHANGELOG "Vitis storage model"): `MemrefBankClassification` marks a bank replicable iff no loop body stores to it more than once; the scheduler (`linkMemoryResource`, both the simplex and the greedy path) then grants it 17 read-or-write slots per cycle, 2 otherwise and for interface memrefs, so the II is ceil((R+W)/17) or ceil((R+W)/2); `--bram-analysis` prices copies = max over pipelined loops of min(16, ceil((R+W)/II) - 1) x the narrow (x18) cost and reports them as `RAM_1WNR` (`replication` object in the debug JSON). Loop-invariant loads are hoisted inside `--convert-affine-to-loopschedule` after the flatten decision (`hoist-invariant` option). Validated on the 13 rep_* kernels (replication.md table): every per-array and total BRAM equal, with the inner reduction loop unrolled by `--debug-unroll` and without `--infer-vitis-split-array` (which still port-splits rep_wr2 / rep_2n_write, the td=auto behaviour; N2).
- **hls-est, "after CSE and forwarding" (T2 review fixes):** R and W are counted after `--convert-affine-to-loopschedule`'s redundant-access cleanup (`cleanupRedundantAccesses`), which runs before the hoist and before every analysis: same-address loads in one block with no intervening may-alias write are merged (`cse-loads`, on by default; the reviewer's 8-loads-of-2-addresses kernel now gives R = 2, a plain RAM, instead of 7 copies); store-to-load forwarding and dead-store elimination (`forward-stores`) are implemented and Vitis-exact per array where the array is live (an unrolled `tmp1[i] +=` becomes one store, 1 BRAM; atax lp1 II 32; attention Q/K `+=` in the QKV loop becomes one store, so Q/K are replicable: 3 copies = Vitis RAM_1WNR on attention_op_p2/p3 and gpt_transformer_p1) but **off by default** (OPEN_ISSUES O7, MEMOS.md M6: since T3's promotion it no longer moves atax / bicg / mvt; it replicates Q/K that Vitis deletes unless `--dead-memory-elimination` runs). The hoist is alias-aware (a store through a memref.cast / subview of the array is a store to the array; an array passed to a call or a region op is never hoisted from). `--bram-debug` shows per access how many loads / stores the surviving op absorbed.
- **Open source agrees (N8):** `MemoryQuerier::queryBRAM` prices a RAM whose bound port vector has n > 2 used slots, not all read-only, as n - 1 x18 copies, i.e. N4's ceil((R+W)/II) - 1 with n = the port slots the binder used (copies == n_ports - 1 on all 216 RAM_1WNR rows with a vector; vectors have at most 17 slots, hence the 16-copy cap). A *read-only* memory with n > 2 read ports is a ROM: ceil(n/2) dual-port copies, not n - 1 (aes sbox, 8 reads/cycle: 4 BRAM, not 7).

## N6. BRAM_18K count per bank: aspect-ratio modes with parity bits (confirmed, 147 kernels, `~/hls-est-work/exp-notes/aspect.md`)
- **Rule:** for a bank of D words x W bits, `BRAM = min over modes m of ceil(W/m) * max(1, P/depth(m))` with `P = 2^ceil(log2 D)` (the address space, not the word count: 2500x18 one-port = 4, not 3; `~/hls-est-work/exp-notes/aspect_chk.md`) and `(m, depth) in {(1,16384), (2,8192), (4,4096), (9,2048), (18,1024), (36,512)}`; the x36 mode is allowed only when at most one port is live per cycle (or the storage is `ram_s2p`); when two ports are live in the same cycle (`ram_2p`/`ram_t2p`, e.g. a read and a write or two reads per iteration of a pipelined loop) the x18 ceiling applies. All columns use the same mode; parity bits count (1024x18 = 1, 2048x9 = 1, 512x36 = 1, 1024x17 = 1, 1024x24 = 2, 1024x40 = 3 one-port / 3 two-port, 2048x72 = 8).
- The declared `bind_storage` type does not change the count by itself; the number of ports the schedule uses does. The `Storage Report` / `design.bindinfo.xml BRAM=` numbers use x18-only packing and are NOT the utilization numbers; only the `* Memory:` table / csynth.xml total count.
- float = 32 bits, double = 64; `ap_int<18>` = `ap_uint<18>`; 1024x1 is a 1-BRAM RAM (consistent with the inclusive 1024-bit threshold).
- **hls-est:** modelled since the T2 commit: `estimateBlocks` (BRAMAnalysis.cpp) is the min-over-modes formula with P = 2^ceil(log2 D); x36 is allowed for RAM_1P / RAM_S2P (one live port), x18 is the ceiling for RAM_2P / RAM_T2P and for every RAM_1WNR copy. Lit test `test/hls-est/Passes/aspect_modes.mlir` pins 1024x18 = 1, 2048x9 = 1, 512x36 = 1 / 2 (one / two ports), 2500x18 = 4, 1024x40 = 3, 3072x20 = 5, 64x32 = 1 / 2.
- **Corrected by N8 (open-source formula + new kernels):** (1) for depth > 4096 Vitis never stacks 2Kx9 / 1Kx18 / 512x36 columns: 4097-8192 words cost ceil(W/2), > 8192 words 2^ceil(log2(ceil(D/16384))) x W, so the min-over-modes rule undercounts when x9 stacking is cheaper (8192x9 = 5 not 4, 6000x27 = 14 not 12, 16384x18 = 18 not 16); D <= 4096 is unchanged. (2) x36 is decided by the bound port vector (SDP = one used port, or one write-only + one read-only port, or two read-only ports): a ROM read twice per cycle is x36 (512x32 = 1), and an explicitly bound ram_2p / ram_t2p whose used ports are {R, W} or a single port is x36 too.

## N7. Partition pragmas, reshape, bind_storage and the automatic partitions that remain with td=off (confirmed, 136 kernels, `~/hls-est-work/exp-notes/partition.md`)
- **array_partition** `{cyclic|block} factor=F dim=d` -> exactly F banks, each `ceil(N_d/F) x (product of the other dims)` words; cyclic/block and dim=1/2 cost the same BRAM. `complete dim=1|2` on a 2-D array -> N_d memory banks (64x32 banks = 1 BRAM each, not registers); only `complete dim=0` or `complete` on a 1-D array removes the memory (registers, 32 FF per element). Bank naming `A_U`, `A_1_U`, ... all sharing module `A_RAM_AUTO_1R1W`.
- **array_reshape** `factor=F` -> one memory of N/F words x F*W bits (64x64 int F=4 -> 1024x128 = 8 BRAM; `complete dim=2` -> 64x2048 bits = 114 BRAM, bound ram_2p).
- **bind_storage** types ram_1p/2p/s2p/t2p cost the same as the auto core for the same access pattern: the count follows the ports used per cycle (ram_1p/s2p with 2 reads per cycle keep 1 BRAM but the loop gets II=2).
- **Port mode:** `ram_1p` when no cycle touches the bank twice; `ram_2p` (18-bit columns) when a cycle holds two accesses (two reads, read+write, or two constant-index reads issued in the same state); `RAM_1WNR` with R-1 copies when a cycle needs R >= 3 reads. Any in-place update of a local array inside a pipelined loop (`acc[i] += ...`) therefore costs the 18-bit column (64x32 -> 2).
- **Automatic partitions with td=off:** (a) `[HLS 214-421]` arrays with <= 4 elements in total (any width/dims) become registers (0 BRAM, alloca gone); (b) `[HLS 214-449]` a dimension whose EVERY access (after unrolling, in every loop) is a constant index is completely partitioned on that dimension (A[64][8] with j unrolled in both loops -> 8 banks of 64x32); (c) an array whose every access is a constant index is scalarised (no memory); (d) a 1-D array written with a variable index and read only at constant indices is NOT partitioned (stays one ram_2p RAM). Order in the log: 214-421/214-449, then 214-270, then 214-248; all before `a.o.1`.
- **Depth rounding (same as N6):** 1100x32 -> 4, 2100x32 -> 8, 5000x32 -> 16, 12000x32 -> 32, 1408x32 (cyclic 3 on 64x64) -> 4.
- **hls-est:** banking keeps `ceil(N_d/F)` bank depth and the pow2 depth rounding + x36/x18 column rule from N6; `complete` on one dim stays BRAM banks (1024-bit threshold: 64x32 = 2048 bits is BRAM). (a)-(c) are implemented by `--infer-vitis-split-array=td=off` (T5; opt-in, the default `td=auto` is the port-pressure inference; `auto-partitions=true` adds them to td=auto): (a)/(c) set `hls.registers` (0 BRAM, status `registers`, no port limit in the schedule), (b) a `complete` spec with `source = "constant-index"`, only on an array with at least one affine access (the arrays memory banking can split); what counts as a constant index (also through an index cast, or the counter of a single-trip loop) is one definition shared with banking (`ConstantIndex.h`), so a constant-indexed access reads one bank. Lit `test/hls-est/Passes/split_array_td_off{,_bram}.mlir`, `split_array_registers_sched.mlir`. Corpus evidence: polybench gesummv `hls_compile.log:52-53` 214-449 on buff_A and buff_B (64 + 64 BRAM; hls-est td=off 134 vs Vitis 135). (b) is only as good as the unroll decisions in front of it: atax / bicg match only with `--auto-pipeline-unroll=float-loads-perfect=true` (O13). Not modelled: several constant dimensions of one array (banking applies the first spec entry; none in the harness subset), dead banks (rep_atax_A_R08: Vitis keeps the 8 banks that are read; `--dead-memory-elimination` after banking gives that), user `complete dim=0` (still banked on dim 1: p2d_comp_d0 64 vs 0).

## N5. BRAM vs. distributed RAM for small arrays (confirmed, 23 kernels)
- **Rule:** a local array with `Words * Bits >= 1024` is implemented in BRAM_18K; with `Words * Bits < 1024` it becomes distributed RAM (memory row `BRAM_18K = 0`, `FF = Bits`, `LUT = ceil(Words*Bits/64)`). The threshold is inclusive and uses the exact element width (64x15 = 960 bits -> LUTRAM; 64x16 = 1024 -> 1 BRAM; 93x11 = 1023 -> LUTRAM; 16x64 = 1024 -> 2 BRAM). Depth alone is not the criterion (128x4 -> LUTRAM).
- **Resources (N8, `queryLUT` / `queryFF`):** LUT = ceil(Words*Bits/64) on 8682 of 8682 LUTRAM rows; FF = Bits x used ports (8680 of 8682; `FF = Bits` alone holds for 7256), i.e. one output register per port when the latency is 1.
- **Kernels:** `~/hls-est-work/exp-src/lutram/lutram_d<depth>_w<bits>.cpp` (1-D buffer written in one auto-pipelined loop, read in another) and `lutram_chk_*` (ap_int<4>/<11>/<15> widths), reports `~/hls-est-work/experiments/lutram_*/<hash>/report/k_csynth.rpt` line 90, notes `~/hls-est-work/exp-notes/lutram_chk.md`.
- **Not yet checked:** whether the threshold changes for ROM (const arrays), 2-D arrays, partition banks, or arrays with two ports in use.
- **hls-est:** fixed in the T2 commit: `meetsBRAMPromotionThreshold` is `sizeInBits >= kBRAMPromotionBits` (1024, MemoryDS.h); element width exact. Lit test `test/hls-est/Passes/lutram_threshold.mlir` (64x16 = 1, 93x11 = 0, 64x15 = 0, 16x64 = 2, 1024x1 = 1, 32x32 = 1).
- **Only reachable end-to-end with the exact shim** (T2 review, finding D3): the harness default shim (`run_hlsest.py --shim scalar`, `shim/scalar/ap_int.h`) maps `ap_int<W>` to the next 8/16/32/64-bit builtin, so cgeist emits `memref<93xi16>` for `ap_int<11> b[93]` and `memref<64xi16>` for `ap_int<15> b[64]`, and hls-est says 1 BRAM where Vitis says 0 (`lutram_chk_d93_w11`, `lutram_chk_d64_w15`). With `--shim exact` (`_BitInt(W)`, commit 0110ede88) the widths are exact and both give 0 = Vitis; the lit test uses hand-written `i11`/`i15` memrefs, i.e. the exact-shim form. Making `exact` the harness default changes every measurement (all baselines would have to be re-run): OPEN_ISSUES.md O6.
- **Side data point (aspect topic):** a 64x32 array with 1 read + 1 write in *different* loops costs 1 BRAM (not 2): the x18-per-port rule only applies when both ports are busy in the same cycle (true dual-port), as for atax's `buff_y_out` (read and written in the same pipelined loop, 2 BRAM).
- **Sequential scopes:** two independent accesses in one state of a non-pipelined region make the array ram_2p too (atax `buff_x`: the 64 hoisted reads issue two per state, 2 BRAM); N12.

## N10. `ap_int<W>` from a double keeps 25 signed bits for 2^24 <= |d| < 2^52 (confirmed; 1 kernel + g++)
- **Rule:** `ap_int_base(double)` (`etc/ap_int_base.h`, constructor from double; not under `__SYNTHESIS__`) shifts the 53-bit mantissa right into an `ap_int_base<FLOAT_MAN + 2, true>` (25 bits, signed) when 0 < 52 - exp < 54, assigns that sign-extended to the W-bit value, then negates for a negative input. |d| < 2^24: exact truncation toward zero. 2^24 <= |d| < 2^52: only the low 25 bits of the integer part survive, read as signed. |d| >= 2^52: exact again (the left-shift path). ## N11. Fixed-point division: C simulation and csynth differ on min / -1 LSB (confirmed; 1 kernel + g++)
- **Rule:** `ap_fixed_base::operator/` has two implementations. C simulation (`#ifndef __SYNTHESIS__`, what g++ with the headers runs) divides in `_W1 = max(W + max(F2,0) + (S2 && !S), W2 + (S && !S2))` bits, so the type's minimum (shifted left by F2) divided by a raw -1 overflows and wraps. csynth (`t.V / op2.V` on the bitwidth integers) gives the exact quotient in the result type (S2 + W + max(F2,0) bits). Every other quotient agrees.
- **Kernel:** `~/hls-est-work/rfx/divk/divk.cpp`, run `~/hls-est-work/experiments/rfx_divk_overflow/d8223ab3ec64`: `ap_fixed<8,8>(-128) / ap_fixed<8,8>(-1)` is 128 in csynth (`store i32 128`, `db/a.o.3.ll:35`) and -128 in g++; `ap_fixed<8,8>(-128) / ap_fixed<4,4>(-1)` 128 vs -128 (a.o.3.ll:39); `ap_fixed<2,1,AP_RND,AP_SAT>(-1.0) /= ap_fixed<1,1>(-1)` is 0.5 in csynth (`i2 1`, the exact 1.0 saturated) and -1.0 in g++. Controls agree: `-127 / -1` = 127, `ap_ufixed<8,8>(200) / ap_fixed<8,8>(-1)` = -200 (`~/hls-est-work/rfx/divk/gxx.out`).
- **hls-est:** `shim/exactclass` follows csynth (exact quotient). For this corner case g++ + the Vitis headers is not the csynth ground truth: `check_shim.py` reports such cases in the known category `divcsim` instead of failing.

## N12. Two accesses per state in a non-pipelined region (confirmed, 33 + 5 kernels, `~/hls-est-work/exp-src/seqports{,2,3,4}/*.cpp`, `~/hls-est-work/exp-src/t6rev/*.cpp`)
- **Rule:** a non-pipelined region is scheduled with the same 2-port RAM core as a pipeline (every access in `db/<module>.verbose.sched.rpt` names `Core .. 'RAM' .. <Ports = 2>`). Up to two accesses of one local array issue in one state, and one such state makes the binder pick `ram_2p` (two reads, or a read and a write) or `ram_t2p` (two writes): x18 columns, 64x32 = 2 BRAM instead of 1. A state never holds more than two and a sequential region never replicates (sp_8ld: 8 independent loads -> four states of two, ram_2p 2). Two accesses share a state when:
  - they lie in one basic block. The arms of an if are predicated into the block, so a load in an arm pairs with one outside it (sp_if, sp_if2: 2), also a load under an if whose condition is the first load (rv_ctrldep: speculated, 2R in one state, ram_2p 2), but the two arms of one if share a port (sp_ifarms, sp_o_ifarms, sp_o_ifst: 1). Accesses in the bodies of two different loops never share a state (sp_sib: two `pipeline off` sibling loops, 1). An inner loop between two accesses of one body separates them **only where the later access feeds something ordered after that loop** (sp_split_loop: `a[i+32]` feeds the add after `inner`, 1; rv_sib3: `a[i+32]` feeds l2, whose recurrence needs l1's result, loads in two states, 1). It does not in rv_sib2 (`t = a[i]; s1 over t; u = a[i+32]; s2 over u`, s2 independent of s1): Vitis outlines the two pipelined loops as `call @k_Pipeline_s1` / `@k_Pipeline_s2` in the parent's block, starts them in ST_4 / ST_5 and issues both loads in ST_3 (`sched_ports.py`: `a peak 2R0W`), ram_2p 2. So "a loop separates" is unconfirmed as a rule (see the exceptions);
  - neither depends on the other: an SSA chain (`a[a[i] & 63]`: sp_dd, sp_o_dd 1; read-modify-write: sp_rmw, sp_o_rmw 1), a store ordered against a may-alias access (`a[5i & 63] = ..; .. = a[i]`: sp_stld_alias, sp_o_stld_alias 1), or a memory order through another array (`x = a[i]; b[idx[i] & 63] = x; y = b[3i & 63]; .. a[(y + i) & 63]`: the load of b may read x; rv_memdep (outer-loop body) and rv_memdep2 (function body): the two `a` loads in two states, `a` ram_1p 1) keeps them apart; provably disjoint addresses (`a[i]` / `a[i+32]`) do not (sp_ldst, sp_stld, sp_o_ldst, sp_o_stld: 1R+1W in one state, ram_2p 2; sp_2st: two stores, ram_t2p 2);
  - for two loads the ASAP distance does not matter: in `a[i] + a[(i*s) % d]` the urem takes 36 states and both loads still issue in ST_41 (sp_far, sp_o_far 2; sp_far2, the two loads feeding different stores, 2).
- **Exceptions (criterion unconfirmed), in both directions:** Vitis list-schedules the parent's basic block, in which a pipelined inner loop is a `call @k_Pipeline_<loop>` (`db/a.o.3.ll`) that ops move across and that can run beside an independent call. (1) With slack around such a call two independent accesses can land in different states: sp_o_2st (the two stores in ST_3 and ST_5), sp_o_2ld_rmw (loads in ST_3 / ST_4), sp_o_far2 (ST_41 / ST_43); also sp_stfar (load in ST_3, the store waiting for a urem in ST_41). The same pairs without slack share a state (sp_2st, sp_far2, sp_o_ldst, sp_o_stld). (2) Two accesses on either side of a loop share a state when each feeds a different, independent loop (rv_sib2 above). Placing every load in the state right before its first consumer starts explains the loads of (1) and (2), sp_far and sp_split_loop, but not the stores (sp_o_ldst's store is at its earliest state).
- **Corpus:** polybench atax `buff_x`, bicg `buff_p`, gesummv `buff_x`, mvt `buff_y1` / `buff_y2`: the 64 invariant reads that Vitis hoists out of the pipelined lp1 / lp3 (inner loop unrolled) into the parent issue two per state (`sched_ports.py`: `atax buff_x peak 2R0W in 32 states`), ram_2p = 2 each. replication.md rep_tri_R08: 8 loads in the sequential lp1 body, one state of two -> buff_A ram_2p.
- **RAM type:** two reads per state bind `ram_2p`, not `ram_t2p` (sp_far, sp_8ld, sp_2ld, sp_straight; corpus: atax `buff_x`, bicg `buff_p`, gesummv `buff_x`, mvt `buff_y1` / `buff_y2`); only two writes per state need `ram_t2p` (sp_2st). - **Evidence:** runs `~/hls-est-work/experiments/t6_sp_<kernel>/<hash>/` and `t6rev_rv_<kernel>/<hash>/` (report, `db/k.verbose.sched.rpt`, `db/a.o.3.ll`); per-state counts with `tools/hls-est-validate/sched_ports.py <run dir>`. ## N14. Non-inlined functions: instances, where their memories are charged, loops at the call boundary, automatic inlining (confirmed; 60 kernels + 27 corpus designs, W3 2026-10-10)
Kernels `~/hls-est-work/exp-src/inline/inl_*.cpp`, runs `~/hls-est-work/experiments/inl_*/<hash>/` (td=off, `vitis_adhoc.py`, every run a fresh v++ 2025.1 csynth, 29-63 s), one result JSON per kernel in `~/hls-est-work/exp-notes/inline/`. The callee in most kernels is `work(in[1024], out[1024])` with a local `buf[1024]` read 3x per cycle in its own pipelined loop (`buf` = RAM_1WNR, 2 copies, 4 BRAM); top-level arrays are ap_memory (0 BRAM). "Instances" = rows of the csynth instance table whose module is the callee; BRAM of a module counts once per instance in the total (Vitis sums instance rows). No log message reports instance sharing: the instance table (and the top latency) is the only evidence. `[HLS 214-131]` = inlined because of a pragma, `[HLS 214-178]` = inlined automatically.
- **R1 Charging (confirmed):** a non-inlined callee's local arrays are listed once in the callee module's memory table and counted once per instance of that module (`inl_a1_once_off` 4 = inlined `inl_a1_once_on` 4; `inl_b2_twice_indep` one `work | buf` row, 2 instances, total 8; `inl_b4_three_indep` 3 instances, 12). For one instance the cost equals the inlined cost: same core, same replication (a1 off/on, `inl_c3_pipe_local` off/on 2/2). Arrays a callee receives as arguments are charged to the caller (lowest common ancestor, N1a "Where an array is charged").
- **R2 Instances inside one parent module (confirmed, 14 kernels):** calls of the same function from one parent get **one instance per call that can run concurrently**; calls that are ordered share one instance. Ordered = a scalar data dependence (`inl_b9_scalar_chain` `g(g(x))`: 1 instance, latency 80 vs 41 for two independent calls in `inl_b10_scalar_indep_off`: 2 instances), or both calls access a common array, read or write, local or top-level port (`inl_b1_twice_dep` via tmp: 1, latency 4119; `inl_b5_indep_same_in`, both only read `in`: 1, 4119; `inl_b8_partial_dep`: 1; `inl_c9_two_loops`: 1), or `#pragma HLS allocation function instances=work limit=1` (`inl_b6_indep_limit1`: 1, 4120). Calls on disjoint arrays run concurrently and get their own instances (`inl_b2` 2 and `inl_b4` 3 with latency 2059 = one call; `inl_b7_indep_local` 2 on caller-local arrays; `inl_g_loopbig_indep2` 2, a callee kept without pragma). One call site in a non-unrolled loop is one instance (`inl_c1_loop` 4 trips: 1, buf 4).
- **R2 in a pipelined loop (confirmed):** independent calls in one iteration get one instance each, and a callee's ROM is duplicated per instance (`inl_c4_rom_one/two/three`: `h` with a 1024x31 `ROM_AUTO_1R` table, 1/2/3 calls per II-1 iteration -> 1/2/3 instances, 2/4/6 BRAM; inlined `inl_c4_rom_two_on` 2 BRAM). Calls that share an array argument are serialized on one instance and the II rises instead (`inl_e3_arg_pipe_twocalls`: two `get2(buf, i)` calls, 2 reads each, 1 instance, `[HLS 200-880]` carried dependence between the `call` operations, Final II 4, buf RAM_1R1W 2 BRAM, no replication). A loop-free callee with a `static` array called once per iteration: 1 instance, II 1 (`inl_c2_pipe_static`: `upd | t` 1024x32 2 BRAM).
- **R3 One instance per parent module (confirmed):** a callee called from two different (non-inlined) parents has one instance in each, whatever the data dependences (`inl_d1_two_parents`: p1 -> work, p2 -> work: 2 instances, 14 = m 2 + p1.t 2 + p2.t 2 + 2 x buf 4; `inl_d2_top_and_parent`: work in top and in p1: 2 instances, 12). So the multiplicity of a module is the number of instance paths from the top (product down the instance tree).
- **R4 Clones (confirmed as observed, trigger unconfirmed):** Vitis clones a callee into `work.1` (module `work_1`, `[SYN 201-103] Legalizing function name 'work.1'`) in the first optimisation stage (`db/a.o.1.ll` defines `work.1`; `a.g.ld.5.gdce.ll` does not) when call sites in one function pass different array argument forms: a row of a 2-D argument vs a whole 1-D array (`inl_c7_loop_and_direct`, `inl_c10_loop_two_sites`: `work(in[k], t); work(t, out[k])` -> work + work_1, 2 instances, 10 BRAM although the calls are serialized, latency 4120 per trip), or the k = 0 call vs the k >= 1 calls of an unrolled loop (`inl_c5_unrolled_loop` `#pragma HLS unroll` over `work(in[k], out[k])`: a.o.3 has 1 call to `@work` and 3 to `@work.1`, 2 instances, 8 BRAM). Same-form call sites are not cloned (`inl_b1`, `inl_b2`, `inl_c9`: rows in both loops), nor are call sites that differ only in constant scalar arguments (corpus: one `conv_via_tiling_3x3` module for 7 calls with different sizes in conv_block_module). Each clone is its own module with its own copy of the callee's arrays.
- **R5 Outlined loops (confirmed as observed, trigger unconfirmed):** a caller loop containing a call is outlined into a module `<fn>_Outline_<loop>` (appears in `db/a.o.3.ll`) when the same function also calls a function outside any loop (`inl_c7_loop_and_direct` and `inl_c11_two_direct_and_loop_other`, the direct call there being a different callee); not when every call is inside loops (`inl_c1_loop`, `inl_c6_loop_plus_inner` with an array declared in the loop body, `inl_c9_two_loops`). Other triggers exist: forgebench diff_orders_p1-p3 outline a loop nest with partial user unrolls that contains no call (top.cpp:120 / :111). The calls inside belong to the outlined module, so a callee called in the loop and outside gets 2 instances even with `allocation ... limit=1` in the caller (`inl_c8_loop_and_direct_limit1`: 8 BRAM, like c7). This is the corpus case below (tiled_attn_module).
- **R6 Caller-owned arrays passed to callees (confirmed):** the caller's array is priced from all its accesses, including the pipelined loops inside non-inlined callees: replication crosses the call boundary (`inl_e1_arg_rd3_off` buf read 3x per cycle in `rd3`'s own pipelined loop: top `buf` RAM_1WNR 4 BRAM = inlined `inl_e1_arg_rd3_on` 4; `inl_e2_arg_wr_rd3` written in `wr`, read in `rd3`: 4). It is not replicated for reads made by a callee that is called from inside a pipelined caller loop: those go through the callee instance's port and raise the caller loop's II (`inl_e3` above; `inl_f2_unroll_off` II 8, la/lo 4 + 4; N3 pu_call_fn_loop_m8_n16 II 8, 2 BRAM vs 30 BRAM inlined). One read per cycle in a callee plus two in the caller: RAM_1R1W 2 BRAM (`inl_e4_arg_rd1_off`).
- **R7 Loops at the call boundary (confirmed; extends N3):** `inline off` stops flattening across the call. `inl_f1_flat_off`: caller `for i<8` around `row()` with a 128-trip loop -> `row | VITIS_LOOP_4_1` pipelined (128 trips), caller loop not pipelined (latency 1073); inlined `inl_f1_flat_on`: `[perfect_nest]` + `[flatten]`, one 1024-trip II-1 pipeline (1029). A callee loop of <= 64 trips under an auto-pipelined caller loop is completely unrolled inside the callee (`[HLS 214-186] ... in function 'row16' completely with a factor of 16`) and the caller loop is pipelined: `inl_f2_unroll_off` (caller 128 trips) II 8, where the inlined nest is flattened into one 2048-trip II-1 loop (`inl_f2_unroll_on`); BRAM equal (8/8) because the 16 accesses per call go through the callee's port and nothing is replicated (R6). Arrays local to such a callee are not partitioned by the unroll (`inl_c3_pipe_local` t 64x32 RAM 2 BRAM, II 64; inlined `_on` also 2 BRAM, II 65).
- **R8 Automatic inlining of callees without a pragma (unconfirmed threshold; 21 kernels: 19 `inl_g_*`, `inl_b9`, `inl_b10`):** Vitis inlines a callee without pragma (`[HLS 214-178]`) iff (callee instructions at Compile/Link, `report/csynth_design_size.rpt` "Instructions per Function", shown as `N (k calls)` = per-call size x calls) x (call sites) <= T with **96 <= T < 122**: inlined at 12x2, 42x2 (scalar bodies), 48x2 (`work` with two 1024-trip loops and a local array: `inl_g_loop_st2` / `_ext2` -> buf duplicated, 8 BRAM), 82x1; kept at 62x2, 82x2, 102x2, 122x2, 162x2, 642x2, 2562x2 and 122x1, 2562x1 (`inl_g_st1_n24`, `inl_g_st1_n512`, `inl_g_ext1_n512`). `static` vs extern linkage, loops and local arrays make no difference at the tested points (`inl_g_st2_n8` = `inl_g_ext2_n8`; `inl_g_st2_n512` = `inl_g_ext2_n512`). A kept callee follows R2: `inl_g_loopbig_dep2` (208-instruction `work`, two dependent calls) 1 instance, 6 BRAM; `inl_g_loopbig_indep2` 2 instances, 8. Unconfirmed: T between 96 and 121, whether the measure is exactly that product, and whether a single call of a `static` function has a bonus (82x1 inlined, 122x1 kept).
- **Corpus (td=off ground truth `results/vitis.json`: the 27 designs with a result whose sources use `inline off`; instance tables, memory rows, and the per-function call counts of `report/csynth_design_size.rpt` at Compile/Link, i.e. before Vitis inlines):** (i) for 23 (21 forgebench, GP_selection fixed/float) the total equals the sum over modules of memory-row BRAM x instance multiplicity + the m_axi adapter instances; the 4 dataflow designs (DGNN_Booster EvolveGCN 1723 vs 1701, convLSTM 1543 vs 1511, flowgnn gin 1158 vs 1090, pna 20600 vs 20502) also have FIFO-channel BRAM outside the memory rows (e.g. gin `compute_CONV_layer` FIFO 4). (iii) Only one module holding memories has more than one instance: tiled_attn_module `grouped_multihead_attention_8_256_4_16_ap_fixed_16_5_s` (V 1 + scores 1), called in `top` inside `for (i < 4)` (loop top.cpp:396, call :412) and directly (:435) with `allocation ... limit=1`: one instance in `top` and one in `top_Outline_VITIS_LOOP_396_1` (R5, reproduced by `inl_c8`), 4 of the 270 BRAM. - **O5 (confirmed, 3 kernels):** Vitis does **not** hoist an inner loop whose bounds and body are invariant in the enclosing loop before its pipeline / flatten decision. `inl_o5_f8` / `inl_o5_i8` (`lp1(i<64) { lp2(j<64) { acc = 0; lp3(r<8) acc += alpha * bA[i][r]; t[i][j] = acc; } }`, float / int): `[perfect_nest] lp1 | lp2`, `[flatten] lp1`, `lp3` unrolled x8 into `lp1_lp2` (4096 trips, II 1), bA RAM_1WNR with 7 copies (`[replicate] ... | 7`, 14 BRAM), total 22; hoisted, the 8 loads would sit in a sequential lp1 body. `inl_o5_i100` (r < 100, int): `lp1_lp2_lp3` flattened into one 409600-trip II-1 pipeline (latency 420119); hoisted, lp3 would run 6400 times. Side observation for the N3 model: in `inl_o5_i8` the unrolled lp3 loads are j-invariant **integer** loads and the nest is still flattened, so N3's integer invariant-load rule applies to loads written directly in the inner body, not to loads of a loop that the decision unrolls.
- **hls-est:** not modelled. cgeist inlines every callee (O10). What the model will need once calls survive (MEMOS decision #11, W3): price a callee's memories once per instance; instances per (clone, parent) = number of mutually concurrent calls (R2), times the parent's multiplicity (R3); calls sharing a memref argument or an SSA dependence are one chain; caller arrays take the replication demand of the callees' own pipelined loops (R6) but not of calls inside a pipelined caller loop (II instead); no flattening across a call, <= 64-trip callee loops unrolled into a pipelined caller (R7, already in `--auto-pipeline-unroll` for `func.call`). R4 / R5 (clones, outlines) and R8 (auto-inline threshold for callees without pragma) are observations without a confirmed trigger; do not encode them before more kernels.
