## 2026-10-10 — hls-est: Vitis integer folds (`--vitis-fold`) and dead-memory elimination (`--dead-memory-elimination`), both opt-in
- **Commit:** the T4 commit (see the m_axi entry above)
- **Files:** lib/Dialect/Resource/Passes/{VitisFold,DeadMemoryElimination}.cpp (new), lib/Dialect/Resource/Passes/CMakeLists.txt, tools/hls-est/main.cpp (`registerVitisCleanupPasses`), lib/Dialect/Resource/Passes/BRAMAnalysis.cpp (`hls.dead_memrefs` -> debug records with status `eliminated_dead`), test/hls-est/Passes/{vitis_fold,dead_memory_elimination,dme_attention_int}.mlir, tools/hls-est-validate/experiment_pipeline.py (ABLATION rows `with-dme`, `with-dme-no-split`, `with-dme-passes-only-no-split`, `with-canon-sccp-no-split`, `with-maxi-no-split`, `with-globals-no-split`, `with-call-latency-no-split`)
- **What:** `--vitis-fold` rewrites integer `divsi / divui / remsi / remui / ceildivsi / ceildivui / floordivsi` by a constant 0 to the constant 0 and applies all canonicalization patterns and folders in the same greedy rewrite (`canonicalize=false`: only x/0); floats are not folded (IEEE). `--dead-memory-elimination` is a module-wide aggressive DCE over memory objects (alloca / alloc / global with its get_global sites and views): roots are returns, calls, stores to arguments or unknown memory, unknown-effect ops and escaping objects (passed to a call, stored, yielded, a global used by several functions); a live load makes its object live, a live object makes its writers live, loop iter_args and if results are tracked per index (dead ones become pass-throughs / 0); then every non-live op is erased. Before each liveness round it deletes stores to non-escaping objects that a later store with the same access overwrites before any read, in the same block or after the enclosing loops / ifs; loads of the same element that only feed its own stores (a promotable read-modify-write accumulator) do not count as reads. The accesses must be equal, so there is no cross-loop DSE (R2). `hls.preserve` does not keep a dead array; eliminated arrays are recorded in the module attribute `hls.dead_memrefs` and listed by `--bram-debug` / `--bram-debug-json` (status `eliminated_dead`, reason).
- **Why:** VITIS_NOTES.md N1, N1a (dead_globals.md R1 write-only / unreached / dead value / x*0, R2 no cross-loop DSE, R5 `1/0 -> 0` and the attention chain, R6 globals). The overwritten-store rule is what LLVM's LICM promotion + DSE do to `scores[i][j] += q*k; scores[i][j] *= 0` (dg_d_apfixed16 a.o.1.ll:1171 `store i16 0`, no Q/K loads).
- **Effect:** lit `dme_attention_int.mlir` (integer attention, scale = divsi(4194304, 0)): Q, K and their MACs removed, 3 BRAM vs 7 for the non-zero-scale control. dead_globals kernels on cgeist output: 13 / 22 exact with and without the cleanups (cgeist already deletes the C-int dead arrays; the 9 misses are R3/R4 narrowing (O18), dg_d_int3 replication, dg_d_apfixed16 (f32 under the scalar shim, O16) and dg_f_twice_off (O10)). Harness subset: `--vitis-fold --canonicalize --sccp --dead-memory-elimination` alone changes no total under the scalar (`dmeonly_nos`) and exact (`x_dmeonly_nos`) shims. Under the exactclass shim (`xc_dmeonly_nos`): attention_op_p1 203 -> 71, tiled_attn_p1 203 -> 71, tiled_attn_p2 55 -> 21, tiled_attn_module 304 -> 108 (|err| on the pre-T4 designs 1390 -> 1232); with `--bram-maxi-adapters` (`xc_dmemaxi_nos`) exact 42 / 73 -> 47 / 73, |err| 1390 -> 1210 (attention_op_p1 73, tiled_attn_p1 73, tiled_attn_p2 23, activation_module / op2 / op3, diff_dims_module_small newly exact; mult_op_p2, mult_op_p3, vec_mtx_p1 lose their adapter cancellation), default pipeline (`xc_dmemaxi_def`) 36 / 72 -> 39 / 72, 2011 -> 1759. forgebench attention_op_p1: scalar shim 406 -> 408 (only the adapter), `--shim exact` 203 -> 205 (f16: 1/sqrt(16) = 0.25 - nothing to fold, Q and K live), `exactclass` shim (integer ap_fixed, `--scalar-wrapper-abi`, c733e425e): 203 -> 73 = Vitis per array (Q, K, BRAM_weights_q, BRAM_weights_k eliminated; BRAM_attn_input 2, BRAM_weights_v 64, BRAM_1 2, V 2, scores 1, mem1 adapter 2). dg_d_apfixed16 under exactclass + the cleanups: 2 = Vitis (V 1, scores 1; Q, K eliminated; it needed the O9 fallback of the robustness entry). tiled_attn_module stays off (108 + 2 vs 270): Vitis keeps four arrays filled by non-inlined `load_*` calls as 0R0W memories (N1a, O16).
- **Reverted?:** no (opt-in). Replaced within the change: an overwritten-store rule that treated every read inside the loop as blocking (it missed the memory-carried accumulator of the exactclass output), and a chain test that let a yielded value stay inside the accumulator chain (lit `@rmw_yield_escapes`).
